# 文書言語ポリシー

Kadoka Othello AI の仕様・設計・運用文書は、**日本語を正本（source of truth）**とする。

## 対象

原則として次を日本語正本とする。

- `README.md`
- `AI_CONTEXT.md`
- `AGENTS.md`
- `doc/*.md`
- GitHub Issue / PR の仕様・設計説明
- 開発・検証・運用手順

コード識別子、API名、schema名、コマンド、ファイル名、外部仕様名など、技術的に英語表記が適切なものはそのまま使用してよい。

ライセンス原文や外部文書の引用は、その文書自身の言語を維持してよい。

## 正本ルール

- 仕様変更は最初に日本語正本へ反映する。
- 英語版だけを先に更新して、日本語版を古い状態にしない。
- 日本語版と翻訳版で意味が衝突した場合は日本語版を優先する。
- 新規仕様書は原則として日本語で作成する。
- READMEやAI支援用入口文書から、日本語正本の場所を辿れるようにする。

## 英語版を残す場合

英語版は補助資料・翻訳版として扱う。

推奨命名:

```text
foo.md      日本語正本
foo.en.md   英語翻訳
```

英語版の冒頭には、少なくとも次を明記する。

```text
This document is a translation.
The Japanese document <path> is authoritative.
```

翻訳版へ独自仕様を追加してはいけない。

## Issue / PR

Issue本文は日本語を基本とする。

PRでは、仕様・設計変更を含む場合に次を確認する。

1. 対応する日本語正本が更新されているか。
2. 英語翻訳がある場合、日本語正本より先行していないか。
3. API名やschema名まで不必要に日本語化していないか。
4. 実装と文書の意味が一致しているか。

## AI支援開発

AI支援ツールは日本語正本を優先して読む。

英語文書が存在しても、日本語正本と競合する内容を採用しない。

Context Routingは読む量を減らすための索引であり、仕様の正本そのものではない。

## 機械チェック

Rule Checkerは、主要入口文書に「日本語を正本」とする方針が存在することを機械的に確認する。

自然言語本文が十分に日本語かどうかを推測するような曖昧なチェックは行わない。

## 設計原則

**仕様の意味を1か所に固定する。日本語文書を正本とし、他言語はその派生とする。**
